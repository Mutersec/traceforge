Built for the quiet part of analysis

No execution. No telemetry. No mystery state. Just bounded parsing and records you can verify.

01

Read-only by design

TraceForge never launches, attaches to, or modifies the target. Every read is bounded before allocation.

02

Evidence, not a screenshot

Each result gets a content-addressed ID, input SHA-256, limitations and a local JSON record.

03

Agent-native

Universal slices

From clone to Evidence in one minute

Node 22 or newer. No accounts, no API keys, no background daemon.

❯ git clone https://github.com/Mutersec/traceforge.git
❯ cd traceforge && npm ci && npm run build
❯ node dist/cli.js scan /bin/ls
TraceForge · scan · mach-o · 3 slices
Evidence ev_157a66f2...
❯ node dist/cli.js inspect /bin/ls --arch arm64
❯ node dist/cli.js diff /bin/ls /usr/bin/true
❯ node dist/cli.js evidence verify-all

What lands on disk

  • Input identity — SHA-256 and size, never a guess.
  • Parser facts — slices, sections, imports, exports, libraries and build metadata.
  • Limitations — stripped symbols, absent directories and capped collections stay visible.
  • Evidence — canonical JSON, atomic write, owner-only permissions, re-authenticated on read.

Need a portable record? evidence export writes a deterministic bundle; evidence import authenticates every record before merging.

Point your agent at it

One stdio server. Five tools. No SDK or cloud relay in the middle.

// mcp.json
{
  "mcpServers": {
    "traceforge": {
      "command": "node",
      "args": ["/absolute/path/to/traceforge/dist/cli.js", "mcp"]
    }
  }
}
  • scan_binary — format, hashes and slice summary.
  • inspect_binary — sections, symbols, libraries; optional architecture.
  • compare_binaries — deterministic structural changes.
  • get_evidence / list_evidence — authenticated local records.

The server speaks newline-delimited JSON-RPC 2.0 over stdio and never writes non-protocol data to stdout.
