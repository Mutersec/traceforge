Built for the quiet part of analysis

No execution. No telemetry. No mystery state. Just bounded parsing and records you can verify.

01

Read-only by design

TraceForge never launches, attaches to, or modifies the target. Every read is bounded before allocation.

02

Evidence, not a screenshot

Each result gets a content-addressed ID, input SHA-256, limitations and a local JSON record.

03

Agent-native

A dependency-free MCP stdio server exposes the same core as the CLI. Six tools, one Evidence contract.

04

Universal slices

Inspect every slice or select one architecture with --arch arm64.

05

Deterministic diffs

Compare sections, imports, exports and slice metadata without host-specific noise.

06

Zero runtime deps

The runtime uses Node built-ins only. The MCP protocol is implemented directly.

From clone to Evidence in one minute

Node 22 or newer. No accounts, no API keys, no background daemon.

❯ git clone https://github.com/Mutersec/traceforge.git
❯ cd traceforge && npm ci && npm run build
❯ node dist/cli.js scan /bin/ls
TraceForge · scan · mach-o · 3 slices
Evidence ev_72e61605...
❯ node dist/cli.js inspect /bin/ls --arch arm64
❯ node dist/cli.js diff /bin/ls /usr/bin/true
❯ node dist/cli.js evidence verify-all

What lands on disk

  • Input identity — SHA-256 and size, never a guess.
  • Parser facts — slices, sections, imports, exports, libraries and build metadata.
  • Limitations — stripped symbols, absent directories and capped collections stay visible.
  • Evidence — canonical JSON, atomic write, owner-only permissions, re-authenticated on read.

Need a portable record? evidence export writes a deterministic bundle; evidence import authenticates every record before merging.

A report anyone can read

Identity badge, sections, symbols and limitations — one standalone HTML file, no external scripts.

  • Verified identity — the report recomputes its Evidence ID.
  • Plain-language summary — format, size, slices, sections and symbols.
  • Visible uncertainty — limitations stay on the page.
  • Self-contained — no scripts, no remote assets.

tforge report /bin/ls --out report.html

The script only calls the CLI — it renders no HTML of its own — then rejects any report over its size cap, audits every tag before keeping the file, and --check re-runs the whole set and byte-compares it. Full gallery notes.

One honest note: inside a report, the member tables are wider than a phone screen, so they scroll sideways inside their own wrapper — nothing overflows a box any more, and long paths and hashes break where they must. The record is complete; only the layout is the limit.

What these reports do not prove

  • No origin. No code signature or notarization ticket was checked; manifest values are self-reported claims.
  • No contents. Archives are hashed, never opened.
  • No behaviour. Nothing was executed, launched or attached to.
  • Not always complete. When a limit stops the walk, the report says which parts are missing.

Point your agent at it

One stdio server. Six tools. No SDK or cloud relay in the middle.

// mcp.json
{
  "mcpServers": {
    "traceforge": {
      "command": "node",
      "args": ["/absolute/path/to/traceforge/dist/cli.js", "mcp"]
    }
  }
}
  • scan_binary — format, hashes and slice summary.
  • inspect_binary — sections, symbols, libraries; optional architecture.
  • inspect_package — a whole .app or directory, the thing behind the gallery reports.
  • compare_binaries — deterministic structural changes.
  • get_evidence / list_evidence — authenticated local records.

The server speaks newline-delimited JSON-RPC 2.0 over stdio and never writes non-protocol data to stdout.
